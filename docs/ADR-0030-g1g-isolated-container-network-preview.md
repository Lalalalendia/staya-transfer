# ADR-0030 — G1g direct QUIC across independent Docker network namespaces

Scope: one bounded **non-production** network-boundary falsifier for [G1f preview PR #43](https://github.com/Lalalalendia/staya-transfer/pull/43), now accepted in main. Must not enlarge File Gate authority, promote experimental relays or create a sync daemon.

**Experiment:** On an Ubuntu GitHub Actions worker, build the exact pinned release and fork `staya-direct-preview` binaries. Put each binary in an unprivileged read-only Ubuntu 24.04 container image. Run sender, allowed receiver and denied outsider as *three different containers* on one private Docker bridge with `--internal` network, no host ports, no relay, all Linux capabilities dropped, `no-new-privileges`, separate /tmp volumes and pids limit. The sender alone can read a synthetic nonsecret 1 MiB+17 source via a read-only mount; receiver has no source mount. Require distinct Docker bridge IPv4 addresses and distinct OS namespace handles, and independently read the receiver's physical staged bytes through a second unprivileged OS process using `docker exec cat` while its separate private tmpfs is still mounted, only after the actual CLI reports full Bao-root verification. Outsider uses its own real ephemeral certificate ID with the same invitation and must fail with an access-related error and no `STAGED` line. Close sender through the operator control channel. Cleanup containers, network and tagged image in `finally`.

The CI-only entrypoint wrapper keeps the Docker container alive **after** the actual receiver CLI returns exit status zero; only then does it print a readiness marker. The host test spawns another unprivileged process using `docker exec cat` inside the still-running receiver's namespace; it reads the real stage file from the still-mounted private tmpfs, compares its bytes, explicitly acknowledges readback inside the container, and requires clean wrapper exit. The Docker daemon's `docker cp` API cannot serve as this test's tmpfs witness. A failing CLI never emits readiness; timeout fails closed. Without this wrapper, Docker discards the tmpfs at container shutdown and no independent readback is possible. It is *not* product runtime code.

A deterministic `inventory.txt` records only semantic claims and hashes, never ephemeral peer IDs or IPs, and must be byte-for-byte identical between pinned release/fork variants. Fail closed on missing Docker privilege, network namespace evidence, connection timeout, refusal that appears unrelated to access policy, missing stage, incorrect physical readback, or incomplete cleanup. No mocking, loopback/host networking fallback or automatic relay enablement.

**Limits:** Three containers on one CI host are not two physical PCs, cannot establish traversal of different LANs, NAT or Internet, do not test unattended operation, Windows ACL, Windows firewall, installed Akula packaging, durable multi-range resume, supervisor #26, signed Device/Vault entitlement, or File Gate / APPLIED. Root + endpoint invitation is manually trusted out-of-band. This test uses only a synthetic public fixture; never upload real user data. Do not mark production P2P ready on PASS.

Acceptance: new exact-head workflow success on both variants plus comparison, Rust/CI scopes remain green, independently inspect artifacts, keep draft until full acceptance.
