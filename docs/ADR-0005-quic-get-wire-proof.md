# ADR-0005 — STY-G1e: genuine Iroh QUIC GET to Staya Bao verification

Status: Draft experiment (2026-10-19); not yet CI-accepted.
Parent: [STY-MASTER-PLAN-02](https://app.notion.com/p/3fe32a84beec81e5acf7c081fe5e0bfd).
Depends on merged [STY-G1d PR #4](https://github.com/Lalalalendia/staya-transfer/pull/4).

## Precise question

Can a real Iroh endpoint, with a real filesystem-backed blob provider, serve one
subrange on an authenticated QUIC stream, and can Staya independently verify
the bytes *actually emitted by the GET protocol*, without first trusting any
remote range inventory or creating a second Akula Sync Core?

## Test design

- Two isolated dependency variants: `iroh-blobs =0.103.1` from crates.io and
  `Lalalalendia/iroh-blobs@a8f5b65d3e4ae0be7d9be7907458b9f1fd56aefa`;
  both independently resolve Iroh 1.3.0 and Bao 0.16.1.
- A real `FsStore` publishes deterministic 256 KiB + 17 B data.
- Real `Endpoint` QUIC connections use Iroh with relay **disabled** and direct
  local endpoint addresses. There is no DNS, public server or S3 access.
- A test-only `ProtocolHandler` wrapper checks the authenticated remote
  `EndpointId` *before delegating* to `BlobsProtocol`, recording and refusing
  an unknown peer. **This is not an implementation of Akula Vault ACL.**
- The consumer uses upstream `get::fsm` with a range `GetRequest`. It receives
  proof-bearing Parent/Leaf items from an Iroh QUIC stream. The items are
  serialized in the original protocol order into Bao proof bytes; Staya
  independently calls `verify_bao_range` against the manifest's trusted root
  and size. This is NOT a raw encrypted-packet capture; Iroh has already
  decoded and validated its response.
- Separate `bao-tree` generation of the same requested range provides a
  byte-for-byte proof reference, in addition to Staya checks.
- Negative gates: forged root, bit-flipped Bao proof, unauthorized endpoint
  and strict 2 MiB in-memory proof bound.
- After accepting one verified range into an in-memory checkpoint, the
  missing-range scheduler must avoid requesting those authenticated bytes.

## Required evidence

- Matrix [release, fork] compiles and runs `interop/quic_get.rs` in CI,
  returns real proof events and logs an explicit success marker.
- Exact commit SHA pinned; dependency lockfiles generated by CI and committed
  for both isolated variants, then *all tests run with `--locked`*.
- GitHub Actions must pass for each variant with full logs. Running only the
  base crate tests or the earlier FsStore local Bao A/B is insufficient.
- No access to user file trees, no production File Gate or revision ACK.

## Exclusions

This test does not validate Roha 2.0's own fork or the `calex794/noq` fork,
multi-device/mobile operation, Wi-Fi-to-LTE migration, relay failover, end-to-end
authorization, reliable partial-file durability, cancellation or restart.
These require independent gates. In particular, Iroh's default `BlobsProtocol`
does not by itself impose Akula document ACL.

Next: compare direct and relay under a dedicated authenticated policy gate,
then STY-G2 durable writer/checkpoint with kill/restart and Windows tests.
