# ADR-0004 — STY-G1d: real FsStore Bao interop A/B

Status: experimental; depends on STY-G1a, G1b and G1c already merged into isolated Staya Transfer main.
Parent plan: https://app.notion.com/p/3fe32a84beec81e5acf7c081fe5e0bfd

## Intent

- Variant release uses crates.io iroh-blobs exactly 0.103.1.
- Variant fork uses Lalalalendia/iroh-blobs commit a8f5b65d3e4ae0be7d9be7907458b9f1fd56aefa, not floating main.
- Both generate the SAME deterministic 8MiB+17B content in a real temporary FsStore, call shutdown, and read the actual external .data and .obao4.
- A pinned bao-tree 0.16.1 encoder creates a 16KiB-chunk-group range response FROM THE STORED OUTBOARD. Staya independently verifies the response against the trusted immutable BLAKE3 root.
- Tests require exact requested bytes; corrupted proof, trailing bytes and wrong root HOLD. Original FsStore files are not mutated in the negative fixtures.
- CI uploads the two authentic Bao-response payloads and manifests as independent artifacts. A comparison job requires exact byte equality, not merely two green unit tests.

## Honest boundaries

- No QUIC wire transfer, direct/relay networking, peer authorization or cross-device test. The range response is encoded locally from real stored outboard bytes with the same pinned Bao codec.
- No crash/partial resume, parallel writer ownership, vault write, Akula File Gate, backup or production publication.
- The two isolated harnesses require Rust >=1.91 because iroh-blobs requires it. The ordinary standalone Staya contract continues to advertise Rust >=1.85.
- Source selections are immutable, but transitive Cargo dependencies are generated by CI for now. Capture and commit BOTH actual generated lockfiles to assert reproducibility; until then call the result functional source-pinned compatibility only.
- Failed CI is a blocker: inspect exact release/fork build failures and pin compatibility without weakening rejection tests or changing Akula.

## Acceptance

1. Release and fork variants compile the same source and generate real external FsStore outboards.
2. Each output verifies with the Staya Bao checker and all corruption tests reject.
3. CI byte-for-byte job compares proof bytes and trusted manifest and succeeds.
4. No changes to Akula main, user documents, or existing S3 sync.

Next after success: authenticated on-wire range response from pinned Iroh/QUIC, durable partial checkpoint, single-owner FsStore lifecycle, then Akula device permissions and File Gate.
