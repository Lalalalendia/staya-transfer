# STY-G2-05h3d - Joint child-registry and pinned actor shutdown laboratory

Status: DRAFT / not production. Parent supervisor issue #26: https://github.com/Lalalalendia/staya-transfer/issues/26 . Release matrix issue #23: https://github.com/Lalalalendia/staya-transfer/issues/23 . Depends on accepted child registry PR #38 and the pinned FsStore actor shutdown witness.

## Problem
Previously the real ActiveFsStore close operation only stopped its SharedAdmission ledger and awaited actual actor shutdown. It did not know which registered OS child processes still had writable handles. Conversely, the child registry had no knowledge of real FsStore. No existing typed API required successful child OS reaping before actor quiescence.

## Experimental interface
The new interop/fsstore_registered_supervisor.rs defines an affine non-Clone owner with transitions RegisteredActiveFsStore -> RegisteredClosingFsStore -> RegisteredQuiescentFsStore. The active session owns BOTH real pinned FsStore plus exclusive StoreLease and its bounded local child registry. Closing consumes the owner (no leftover public child-registry/actor handles), closes child registration and stops FsStore admissions. An explicit bounded reap_registered_children is required. Only after a successful native child kill/reap, zero outstanding registered children, drained actual Bao permits, physical fence validation and real pinned actor shutdown may the quiescent witness be constructed.

The new test runs a separate trusted OS child from the current test executable. It blocks before receiving private stdin ARM; after ARM it opens a real writable file descriptor to a disposable marker inside the store root, writes and syncs the marker, and holds its descriptor while blocked. The parent owns a real pinned actor, the store lock and an imported authenticated Bao range. It must reject quiescence while the child is registered, confirm OS lock is still BUSY, explicitly kill/reap the child, reject quiescence while an import permit still lives, then await real actor shutdown and independently re-audit the sparse physical Bao. Closing the quiescent witness only drops the OS handle, without LOCK_UN; the next owner cold-opens the FsStore and checks the same Bao bytes. No checkpoint is created by actor closure or child reaping.

Exact-head acceptance requires Linux pinned release/fork and native Windows release/fork, Rust fmt and Clippy -D warnings, existing custody and FsStore gates, and unchanged Bao/QUIC byte comparisons. No test suppression, fabricated clean ACK or unconditional unlock.

## Exclusions and next step
This is a trusted child cooperation experiment, not proof against arbitrary processes that ignore ARM or inherit handles. Command::spawn is not suspended launch and stdin is not authenticated/versioned IPC. The entire wrapper exists only in the interop test crate, not Staya Core or Akula. Child hard kill does not prove graceful worker data flush; marker is never a checkpoint. No Linux pidfd/PDEATHSIG, Windows kill-on-close Job Object, process credential binding, cancellation-safe bounded actor startup abort, pathname pinning against adversarial swaps, power-loss guarantees or Windows directory durability. The existing abandoned-actor lock retention is still LAB-only and unacceptable for production. Issue #26, G2-06 and Akula Production File Gate remain HOLD.

Production follow-on: move the entire pinned FsStore actor and OS lease into a contained child process with verified native parent-death protection, authenticated local IPC and OS-verified child registry; enforce registration before any writing. Closing must prove all child exits, actual actor shutdown and pinned physical root identity before a host-local quiescence witness. Failure remains HOLD until isolated owner-process exit is verified.
